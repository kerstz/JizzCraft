# Licences of what ships

JizzCraft itself is MIT OR Apache-2.0 (`LICENSE-MIT`, `LICENSE-APACHE`, `NOTICE`).

## Rust dependencies

`THIRD-PARTY.html` lists every Rust crate linked into the binaries with its
licence text. It is generated by `cargo about` from `about.toml` and
`about.hbs` and staged by `cargo xtask dist` into `share/licenses/jizzcraft/`
(Windows zip: `licenses/`). The accepted list matches `deny.toml`. Releases
fail if `cargo-about` is missing (`CI=true`); local builds only warn.

## GStreamer (bundled in the Windows zip and the AppImage)

GStreamer and the plugins we bundle are LGPL-2.1. Each bundle carries
`licenses/gstreamer/LGPL-2.1.txt` and `SOURCE.txt`: version, upstream source
URL (<https://gstreamer.freedesktop.org/src/>), the bundled plugin files and
a note that the DLLs/.so files are replaceable. The Linux packages (deb, rpm,
Arch, tarball) do not bundle GStreamer; they use the distribution's.

## No GPL plugins

The Windows plugin list contains only LGPL/BSD plugins (core, playback,
isomp4, matroska, vpx, opus, vorbis, dav1d, libav, d3d11, wasapi, ...). No
x264, x265 or "ugly" GPL plugin is bundled. The AppImage script additionally
deletes the known GPL plugins (x264, x265, mpeg2dec, a52dec, dvdread, ...)
that linuxdeploy may copy from the build host.

Decision: `gstlibav` loads FFmpeg. The Windows installer's FFmpeg is an LGPL
build and stays. The **AppImage ships without `gst-libav`**: FFmpeg comes from
the build host, whose licence options are not ours to vouch for. Codecs then
come from the user's system GStreamer, and `jizzcraft-cli doctor` says which
package to install.
